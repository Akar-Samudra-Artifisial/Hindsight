### Fixed

- "Analyze again" di panel insiden yang ditolak (mis. insiden tidak terlihat) tidak lagi diam: pesan alasannya tetap tampil, tidak langsung terhapus oleh reload panel. Setiap resolver UI yang menolak (`resolver refused`), menunggu database (`resolver setting up`), atau gagal (`resolver failed`) kini menulis log beserta nama resolver, sehingga klik Analyze/Write test dossier yang tidak mengantre job bisa dilacak di `forge logs`.
- Ikon sumber "Hindsight signals" (connector Teamwork Graph) rusak di Rovo Search: `graph:connector` kini memakai URL https PNG 256×256 (`docs/assets/connector-icon-light.png`, `connector-icon-dark.png`) sesuai contoh dokumentasi, bukan `resource:` SVG.
- Load demo data di production gagal sebelum langkah 1 dengan `SyntaxError: Unexpected non-whitespace character after JSON at position 4`: Forge SQL mengembalikan setting string `demo_t0` (kolom JSON) tanpa tanda kutip, lalu `parseJsonColumn` mem-parse `2026-…`. Kolom JSON yang bukan JSON valid kini dipakai apa adanya. Respons 2xx Jira/Confluence yang bukan JSON kini gagal dengan pesan yang menyebut endpoint, dan log kegagalan job demo menyertakan stack.
- Halaman setup tidak lagi menampilkan "Project … was created by Hindsight" untuk project/space demo yang sudah dihapus. Di antara job, `getDemoJob` mengecek keberadaan container dan menampilkan "… no longer exists; Load demo data will create it again."; insiden demo di INC yang terhapus tidak ditautkan lagi.
- Load demo data kini berhasil di site tanpa Jira Service Management (sebelumnya gagal di langkah 2/10 dengan `Jira 400: projectType: An invalid project type was specified`). Seed mengecek `GET /rest/api/3/project/type/service_desk/accessible` lebih dulu dan tetap menangkap 400 `projectType`; bila JSM tidak ada, INC dibuat sebagai project software (template sama dengan PAY), tiket pelanggan dibuat sebagai Task, dan insiden sebagai Bug (atau Task). Tiket pelanggan diberi label `hindsight-demo-customer`, sehingga filter tetap memberi bonus "closed without fix" dan hint `customer_complaint` walau sumbernya `jira`; empat sinyal demo tetap lolos. Penutupan "Cannot Reproduce" jatuh ke Done tanpa resolusi bila resolusi ditolak. Halaman setup dan progres job menampilkan catatan mode tanpa JSM.
- Load demo data: project atau space demo yang tercatat di `demo_artifacts` tetapi sudah dihapus dari Jira/Confluence kini dibuat ulang beserta isinya; slot, baris skenario, dan insiden lama di dalamnya dilupakan, bukan dianggap masih ada. - Satu notice tidak lagi memicu dua rantai retry paralel (event trigger asli + salinan cadangan dari "Post a new provider notice"). Pengiriman pertama memegang lock rantai per artefak (`sentinel-chain:…`, 15 menit) sampai rantainya selesai. Pengiriman attempt-1 kedua dilewati dengan skip `chain_active`.
- Teks setup setelah memposting notice kini jujur: Sentinel biasanya berkomentar dalam beberapa menit, setelah notice terindeks Confluence search (sebelumnya "Within a minute").
- Sentinel kini bisa membaca artefak Confluence lagi. Sebelumnya consumer gagal dengan `Confluence get content … 410: This deprecated endpoint has been removed.` karena v1 `GET /wiki/rest/api/content/{id}` sudah dicabut. Halaman kini dibaca lewat v2 `/pages/{id}?body-format=storage`, dan space key lewat v2 `/spaces/{id}`. Komentar dibaca lewat v2 `/footer-comments/{id}`, dengan fallback `/inline-comments/{id}`. Bila v2 komentar ditolak (401/403, karena app belum punya scope `read:comment:confluence`), komentar dibaca lewat CQL search v1 `id = … AND type = comment`. Komentar yang belum terindeks diantre ulang 60 detik, maksimal 3 kali. Kegagalan baca permanen (400/404/410) dicatat sebagai skip `read_failed_<status>`, tanpa retry. Akun app dipelajari dari penulis v2 komentar yang diposting Sentinel. Karena v2 tidak memberi `accountType`, penanda Sentinel kembali dihitung sebagai buatan app bila tipe akun penulis tidak diketahui.
- Sentinel tidak lagi memposting ganda bila consumer mati setelah komentar terkirim tetapi sebelum alert ditandai `posted`: baris `failed`/`posting` dianggap sudah terkirim saat dedup.
- Sentinel: `updated:page` tidak lagi memicu alert ulang tiap 24 jam. Dedup untuk issue/halaman berlaku seumur hidup per (rute, artefak); komentar tetap per comment id.
- Sentinel: artefak yang gagal diposting tidak lagi menambah baris `failed` di tiap event. Percobaan dibatasi satu per jam per artefak (kecuali 429, yang diulang antrean) dan maksimal 3 kali.
- Batas mingguan Sentinel kini atomik: baris alert disisipkan dulu, lalu kuota dihitung ulang dan alert dibatalkan (`skipped`) bila lewat batas. Ada juga batas harian global `sentinel_daily_cap` (default 200).

### Security

- Metrik dan daftar rute reach hanya dihitung dari sinyal yang bisa dilihat pemanggil; rute yang seluruh sinyalnya tak terlihat disembunyikan dan tidak dihapus oleh pemanggil itu.
- Dossier Teamwork Graph (terlihat semua orang) hanya menyebut tipe sumber rute teratas ("a Confluence space"), bukan key-nya.
- Action reach: cloudId diambil dari context pemanggil lebih dulu (payload hanya fallback tervalidasi), dan balasan memuat catatan bahwa nama team/space/project/label adalah data tak tepercaya.
- Langkah reach yang tersimpan membulatkan waktu ke hari, dan node "people in no team" tidak membawa peran atau waktu.
- Prompt penilai `score-v2`: ringkasan dan kata kunci insiden juga dibungkus elemen data tak tepercaya `<incident>`.
- Deskripsi action `confirm-signal` dan prompt agen: hanya dipanggil atas permintaan eksplisit pengguna untuk sinyal tertentu. Keluaran `find-prior-signals` menandai `quote`, `title`, `reason` sebagai teks tak tepercaya (`untrustedFields`, `untrustedNote`).
- Signal card hanya merender link `https:`; URL lain tampil sebagai teks.

- Dossier Teamwork Graph (terlihat semua pengguna site) hanya ditulis untuk insiden demo. Penulisan untuk semua insiden adalah opt-in admin lewat setting `dossier_all_incidents` (default mati; UI menyusul minggu 6).
- Komentar Jira yang dibatasi ke role/grup (`visibility`) dan komentar internal JSM (`jsdPublic: false`) tidak disimpan dan tidak menjadi kandidat, karena izin pembaca hanya dicek per issue.
- Incident key divalidasi ulang sebelum masuk JQL; project/space key hanya lolos lewat regex whitelist lalu diberi tanda kutip.
- Komentar Sentinel kini netral: hanya menyebut team tujuan, "a past incident in this area", key insiden, dan link panel. Kata kunci yang cocok dan sumber rute tidak lagi ditulis. Di project JSM (`service_desk`), komentar dikirim sebagai catatan internal (`sd.public.comment` internal) sehingga tidak terlihat pelanggan.
- Pause/Resume rute hanya untuk Jira administrator (`mypermissions` ADMINISTER sebagai pengguna). Approve tidak berubah, dan UI menampilkan pesan bila permintaan ditolak.
- `escapeXml` disatukan di `src/core/xml.ts` dan kini juga meng-escape `'`.
- Penanda `[Hindsight Sentinel]` yang diketik manusia tidak lagi membuat artefaknya dilewati. Artefak dianggap buatan app hanya bila penulisnya akun app.
